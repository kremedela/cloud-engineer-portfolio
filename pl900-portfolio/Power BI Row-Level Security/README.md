# Power BI Row-Level Security (RLS)

## 🎯 Objective
Implement Row-Level Security (RLS) in Power BI to restrict data visibility by user roles, ensuring users only see the data they are authorized to access.

## 🧠 Skills Learned
- Creating security roles in Power BI Desktop  
- Writing DAX filters for RLS  
- Assigning users to RLS roles in the Power BI Service  
- Testing RLS as different users  
- Publishing secured datasets and reports  

## 📁 Lab Structure
This lab contains:
- **RLS DAX Definitions**
- **Power BI Desktop Role Configuration**
- **Power BI Service Role Assignments**
- **Testing Procedures**
- **Screenshot Points**

## 📝 Short Summary of Lab Steps
1. Import dataset into Power BI Desktop  
2. Identify columns to use for RLS filtering  
3. Create RLS roles and DAX filters  
4. Publish dataset to Power BI Service  
5. Assign Azure AD users to roles  
6. Test RLS in Power BI service  
7. Validate filtered report views  

## 🛠 Tools & Services Used
- Power BI Desktop  
- Power BI Service  
- Azure Active Directory  
- DAX Language  

## 🔑 Prerequisites
- Power BI Pro license  
- Dataset with user or department fields  
- Azure AD users created to test RLS  
- Power BI workspace with Member/Admin permissions  

## 🎉 Expected Outcome
A fully functional Power BI report with active Row-Level Security roles that restrict data by user identity, validated in service under test conditions.
